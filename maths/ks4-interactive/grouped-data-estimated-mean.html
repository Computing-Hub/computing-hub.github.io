Grouped Data and the Estimated Mean

When data is measured rather than counted, almost every value is different, so we sort it into groups. Grouping makes a big data set readable, but it hides the exact values. This page shows how to work with a grouped table anyway: which class is most common, which class holds the median, how to estimate the mean and the range, and how to draw a frequency polygon, and exactly why each answer is only an estimate.

GCSE subject content (Statistics): interpret and construct tables and diagrams for grouped data; interpret, analyse and compare distributions through appropriate measures of central tendency (median, mean, mode and modal class) and spread (range)

Before you start. This page builds on the KS3 page frequency tables: tallying, the mean from a frequency table (total of f × x ÷ total of f), and the median position (n + 1) ÷ 2 with running totals. If those feel shaky, do that page first. You also need the meaning of the inequality signs ≤ and < and the mode, median, mean and range from averages and range.

1 · Why group data?

Here are the times, in minutes, that 40 pupils spent on their phone before going to sleep. Time is continuous data (it is measured, so it could be 27 minutes or 27.4 minutes), and nearly every value is different. A table with one row per value would be as long as the list.

Each group is a class interval (or just class). Its width is upper end − lower end. Choosing the width is a trade-off: narrow classes keep more detail but give a long, bumpy table; wide classes give a short table but hide the shape. Between 4 and 8 classes is usually sensible.

2 · Class intervals: ≤ and <

Every value must belong to exactly one class, so the class boundaries are written with inequalities. The class 20 ≤ t < 30 reads "t is at least 20 and less than 30": 20 is in it, 30 is not (30 starts the next class). Some questions write classes the other way round, 20 < t ≤ 30: now 20 is not in it but 30 is. Always read the signs; the value on the ≤ side is the one that's included.

With discrete (counted) data, classes are written like 0–4, 5–9, 10–14. There are no gaps to worry about, because a value like 4.5 can't happen.

3 · The modal class and the class containing the median

Once data is grouped, the exact values are hidden. We can't give the mode or the median as a number, but we can say which class they are in.

  • The modal class is the class with the highest frequency. Answer with the class, e.g. "20 ≤ t < 30", never with the frequency 12.
  • For the class containing the median, find the median position (n + 1) ÷ 2, then add up the frequencies as you go down the table (the running total, also called cumulative frequency) until you pass that position.

Try it

Common mistakes. Picking the class in the middle of the table (that ignores the frequencies). Giving the median position (20.5) as the answer. Giving the modal class's frequency instead of the class. And: the median does not have to be in the modal class. Here it is, but it often isn't.

4 · Estimating the mean with midpoints

For an ungrouped table the mean is total of f × x ÷ total of f. In a grouped table there is no single x for each row. We know 12 pupils spent between 20 and 30 minutes, but not exactly how long. The fair guess is that, on average, they sat in the middle of the class. So we pretend every value is at the class midpoint:

midpoint = (lower end + upper end) ÷ 2

and then do exactly what you did for an ungrouped table, with the midpoint in place of x:

estimated mean = total of f × midpoint ÷ total of f

Exam traps.

  • Using the class ends (10, 20, 30, …) instead of the midpoints.
  • Dividing by the number of classes instead of the total frequency.
  • Adding the midpoints and dividing, which ignores the frequencies.
  • Discrete groups: the midpoint of 1–10 is (1 + 10) ÷ 2 = 5.5, not 5.
  • Unequal widths change nothing: still (lower + upper) ÷ 2 for each class.

Sense check: the estimate must lie inside the table's range of classes, and usually near the classes with the biggest frequencies.

5 · Why it's only an estimate

The real 40 times are shown below as teal dots, sorted into their classes. The estimated mean uses only the table, so it can't see where the dots really sit inside each class. Slide every value to the bottom or top of its class, as if the data were different: the table doesn't change, so the estimate doesn't move, but the true mean does.

With the real data, the estimate (28.25 minutes) is very close to the true mean (1132 ÷ 40 = 28.3 minutes), because within each class some values sit below the midpoint and some above, and they roughly cancel out. But the table alone can't guarantee that. All it can promise is that the true mean lies somewhere between the "all at the bottom" mean and the "all at the top" mean. So in an exam, "explain why your answer is an estimate" earns its mark with: we don't know the exact values; we assumed every value in a class was at its midpoint.

6 · Estimating the range

The range is largest value − smallest value, but a grouped table hides both. The smallest value could be anywhere in the first class that has any data, and the largest anywhere in the last class with data. The usual estimate is the biggest the range could be:

estimated range = upper end of the last class − lower end of the first class

For the phone data that is 60 − 0 = 60 minutes. The true range is 58 − 3 = 55 minutes. Trap: ignore classes with frequency 0 at either end: if nobody is in them, the data doesn't reach them.

7 · Frequency polygons

A frequency polygon is a quick picture of a grouped table. For each class, plot a point at (midpoint, frequency), then join the points in order with straight lines. You don't join the last point back to the first, and you don't draw bars. Why the midpoint? It's the same assumption as the estimated mean: the point stands for the whole class, so it goes in the middle of it. If you draw the bar chart too, the polygon passes through the middle of the top of each bar.

Frequency polygons are best for comparing two distributions: draw two on the same axes and they don't hide each other the way two bar charts would. That's on the comparing distributions page.

8 · Practice: estimate the mean and the range

Modal class: the highest frequency is 12, so the modal class is 20 ≤ t < 30.
Median position: n = 40, so (40 + 1) ÷ 2 = 20.5: halfway between the 20th and 21st values.
Running totals: 4, 11, 23. The first two classes hold pupils 1–11; the third holds pupils 12–23. Both the 20th and 21st are in it.
Answer: the median is in 20 ≤ t < 30.
Estimate the mean (equal classes)

Same table. Work out an estimate for the mean time.

Midpoints: (0 + 10) ÷ 2 = 5, then 15, 25, 35, 45, 55.
f × midpoint: 4 × 5 = 20, 7 × 15 = 105, 12 × 25 = 300, 9 × 35 = 315, 5 × 45 = 225, 3 × 55 = 165.
Total of f × midpoint: 20 + 105 + 300 + 315 + 225 + 165 = 1130. Total of f: 40.
Estimated mean = 1130 ÷ 40 = 28.25 minutes. Sense check: inside 0 to 60 and close to the busiest class, 20 to 30 ✓

Unequal class widths

The masses w (kg) of 20 parcels: 0 < w ≤ 20: 5; 20 < w ≤ 30: 9; 30 < w ≤ 50: 6. Estimate the mean mass.

Midpoints: (0 + 20) ÷ 2 = 10; (20 + 30) ÷ 2 = 25; (30 + 50) ÷ 2 = 40. Different widths, same rule.
f × mid: 5 × 10 = 50; 9 × 25 = 225; 6 × 40 = 240. Total = 50 + 225 + 240 = 515.
Total of f: 5 + 9 + 6 = 20.
Estimated mean = 515 ÷ 20 = 25.75 kg.
Estimate the range, and explain the estimate

Heights h (cm) of plants: 0 ≤ h < 10: 0; 10 ≤ h < 20: 6; 20 ≤ h < 30: 11; 30 ≤ h < 40: 3; 40 ≤ h < 50: 0. (a) Estimate the range. (b) Why can't you find the range exactly?

Ignore the empty end classes: nobody is in 0 ≤ h < 10 or 40 ≤ h < 50, so the data runs from the 10 ≤ h < 20 class to the 30 ≤ h < 40 class.
(a) Largest possible range = 40 − 10 = 30 cm. (50 − 0 = 50 wrongly includes the empty classes.)
(b) The table doesn't show the actual smallest and largest heights, only which classes they are in.
Exam-style: find a missing frequency

Classes 0 ≤ x < 10, 10 ≤ x < 20, 20 ≤ x < 30 have frequencies 4, k and 6. The estimated mean is 16. Find k.

Midpoints 5, 15, 25. Total of f × mid = 4 × 5 + 15k + 6 × 25 = 20 + 15k + 150 = 170 + 15k.
Total of f = 4 + k + 6 = 10 + k.
Equation: (170 + 15k) ÷ (10 + k) = 16, so 170 + 15k = 160 + 16k.
Solve: 170 − 160 = 16k − 15k, so k = 10. Check: (20 + 150 + 150) ÷ 20 = 320 ÷ 20 = 16 ✓

Quick check

What you've learned

  • Continuous data is grouped into class intervals. In a ≤ x < b, a is included and b is not; in a < x ≤ b it's the other way round. Discrete groups look like 0–4, 5–9.
  • The modal class has the highest frequency. The class containing the median is found with position (n + 1) ÷ 2 and running totals. Answer with a class, not a number of people.
  • Midpoint = (lower end + upper end) ÷ 2, also for discrete groups (1–10 → 5.5) and unequal widths.
  • Estimated mean = total of f × midpoint ÷ total of f. Never divide by the number of classes.
  • It's an estimate because the exact values are hidden; we assume each value is at its class midpoint. The true mean lies between the mean using lower ends and the mean using upper ends.
  • Estimated range = upper end of the last class − lower end of the first class, ignoring empty end classes.
  • A frequency polygon plots (midpoint, frequency) and joins the points with straight lines.
